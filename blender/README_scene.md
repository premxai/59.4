# 4:37: winter-storm city scene

`4_37_city.blend` is generated by `scripts/build_city.py` (geometry, zones, cameras), which imports
`scripts/looks.py` (materials, sky, fog, snowfall, SIM_CONTROL and drivers). The build is
deterministic: rebuilding gives the same city, the same window pattern and the same camera transforms.

```
blender -b --factory-startup --python blender/scripts/build_city.py -- --out blender/4_37_city.blend
```

Blender 5.2, EEVEE, 1920×1080 (CAM_Split 960×1080), 30 fps. Units: metres; +X east, +Y north,
city centre at the origin.

## Driving the scene

Everything visual is reached by setting/keyframing custom properties on the empty **`SIM_CONTROL`**
(all floats, 0–1). No material or object needs to be edited by hand.

| Property | Default | Drives |
|---|---|---|
| `zone_01` … `zone_16` | 1 | Power of that zone: multiplies its window, street-surface, street-lamp and rooftop-light (beacon, roof edge) emission. 0 = fully dark |
| `zone_crit` | 1 | Hospital + water plant. Multiplies emission; below 1 it also switches off windows progressively and warms the light, so **≈0.3 reads as backup-generator lighting** |
| `zone_gas` | 1 | Compressor station + pumpjack field: site lights, light pools, and the pumpjack motion (pumpjacks stop at 0) |
| `snow_amount` | 1 | Blue-white snow on ground, roofs, roads, infrastructure tops, with a subtle sparkle (0 = dry winter ground) |
| `frost_amount` | 1 | White-blue frost/ice on turbines, rotors, pylons, substations, wellheads, power lines (ice coat), walls (subtle) |
| `snowfall` | 0.5 | Density of the falling-snow particles (fraction of 160k flakes kept around the active camera) |
| `sky_time` | 0.5 | 0 late afternoon (overcast), 0.5 dusk (blue horizon, pink/violet band), 1 deep night (moonlight only). Also drives sun/moon strength and sun elevation |
| `turbines_running` | 1 | Fraction of turbines spinning, in fixed order `Rotor_01` → `Rotor_30` (rotor *k* runs while `turbines_running*30 > k-1`). Stopped rotors park at a fixed angle (no slow-down) and look iced |
| `gas_plant_on` | 1 | Steam plumes `Steam_01..03` (density + under-glow) and gas-plant site lights + light pools |
| `line_glow` | 1 | Glow of all `Line_*` transmission lines (power flowing) |
| `battery_glow` | 1 | Battery-yard status light strips |
| `winterized` | 0 | Orange heat-trace glow (cable runs + clamp bands) on every `Wellhead_*` flowline and wellhead, the `Compressor_01` pipe rack, vessels and vent stack, and the gas-plant fuel-gas pipes. Independent of `zone_gas`: if heat trace should need grid power, have the data script send `winterized × zone_gas`. *Added on request* |
| `aviation_lights` | 1 | Red blinkers on the turbine nacelles (independent of `turbines_running`; real aviation lights keep blinking when blades are frozen). *Added with approval: not in the original brief* |

Where the drivers live:
- **`NG_Globals`** shader node group: one driver each for snow, frost, sky, gas plant, line glow,
  battery glow, aviation lights, winterized, plus `blink` (1.5 s period, on at frame 1) and `time` (frame/30).
  Every material reads these through the group.
- **One `power` Value node per zone material** (`MAT_Zone_01…16`, `MAT_Zone_CRIT`) and in
  `MAT_GasField_Lights` / `MAT_GasField_Pool` (zone_gas).
- **Objects:** `Rotor_XX` (rotation + `run` property used by the rotor frost), `Wellhead_XX_Beam`
  (nodding), `Sun` / `Moon` lamps, and the `Snowfall` geometry-nodes modifier input.
- All drivers are *simple expressions*: they run without enabling Python auto-execution.
- When setting properties from a script in background mode, call `SIM_CONTROL.update_tag()` (or
  keyframe them) so drivers re-evaluate before rendering.

Window pattern: each window's on/off state is a pure function of its world position and a fixed
per-building seed (`bid` face attribute), with nothing time-based or random per render. It is
therefore identical in every still and every animation frame. 60–80 % of windows are lit per building.

| `CAMERAS` | `CAM_Wide`, `CAM_Street`, `CAM_Aerial`, `CAM_Split`, `CAM_Fly` (+ `CAM_Fly_Target`) |

Each city zone holds `Bldg_Zone_XX` (all its buildings, one mesh) and `Streets_Zone_XX` (its roads and
street lamps). The face attribute `btype` tells the shader what each face is
(0 house, 1 mid-rise, 2 tower, 3 industrial, 4 road, 5 lamp, 6 facility, 7 plain, 8 rooftop beacon,
9 roof-edge light). Rooftop beacons (towers > 110 m, blinking with the turbines) and roof-edge lights
(~40 % of towers > 55 m) belong to their tower's zone.

`SIM_CONTROL` sits at the scene root (not in a collection).

## Cameras

All fixed cameras are locked (`lock_location`/`lock_rotation`, custom property `LOCKED`) and are
defined numerically in `build_city.py` (`CAMS`), so rebuilding never moves them. Each camera
stores its render size in `res_x`/`res_y`.

| Camera | Size | Use |
|---|---|---|
| `CAM_Wide` | 1920×1080 | Elevated 3/4 aerial from the south-east; hero view; light layers |
| `CAM_Split` | 960×1080 | Split-screen view: whole city, gas plant, pumpjack field + compressor, wind farm; light layers |
| `CAM_Street` | 1920×1080 | Ground level at the east edge, looking along the transmission line to downtown; previews/animation |
| `CAM_Aerial` | 1920×1080 | High, near top-down overview + zone map; previews/animation/zone ID |
| `CAM_Fly` | 1920×1080 | 20 s (frames 1–600) fly-over: wind farm → pumpjack field → over the city → ends exactly in the CAM_Wide framing |

### Light layers and bases (web-app compositing)

- Settings for every base and layer: View Transform **Standard**, Look None, exposure 0, gamma 1,
  no compositor/bloom/glare, 64 samples, **PNG RGB 16-bit**, frame 1 (all blinkers on), falling snow 0.
- **Bases:** all zones, `gas_plant_on`, `line_glow`, `battery_glow`, `aviation_lights` **and `winterized`** = 0;
  `frost_amount` = `snow_amount`. Lit by sky, sun and moon only.
- **Layers:** sky/world strength 0, sun and moon off, `snow_amount` = `frost_amount` = 1, exactly one
  control = 1, everything else 0, which gives pure emission on black. `infra_turbines` = `aviation_lights` = 1,
  `infra_winterized` = `winterized` = 1.
- **Compositing:** decode each PNG from sRGB to linear, then compute
  `final = base + sum(control_value * layer)`, then tone-map/bloom. Spot check: base (sky 0.5, snow 1)
  plus all 23 layers versus an everything-on render with the same settings differs by
  **0.02/255 on average (99th percentile 0.2/255)** for both cameras.
- Emission does not light other surfaces (no ray-traced GI), which is what makes the layers exactly additive.
- `zone_crit` between 0 and 1: in Blender, values below 1 also turn off some hospital windows and warm
  the light (backup generators). The web app's linear scaling of `zone_crit` gives a dimmer but
  otherwise identical hospital.
- CAM_Wide does not show the gas plant, so `CAM_Wide__infra_gasplant.png` is black and the CAM_Wide
  steam overlays are fully transparent. They are kept so every camera has the same file set.

### Steam overlay

`{CAM}__overlay_steam__sky{0|05|1}.png`: the plume only, **RGBA PNG 16-bit, straight alpha** (Film >
Transparent), `gas_plant_on` = 1, `snow_amount` = 1, same settings and exposure as the bases. Every other
object is a holdout, so buildings in front of the plume mask it correctly; fog and falling snow are off.
Draw it over the base with opacity = `gas_plant_on`.

### Zone ID maps

`{CAM}__zone_id.png` for CAM_Wide, CAM_Split and CAM_Aerial: flat emission in the legend colour for
every object in a zone collection (buildings, streets, lamps; Zone_CRIT and Zone_GAS included), black
elsewhere. **PNG RGB 8-bit, no anti-aliasing** (filter size 0, 1 sample), so every pixel is exactly a
legend colour or black. This was verified: 18/18 zones present per camera, 0 off-legend pixels.
`zone_id_legend.json` maps `Zone_01`…`Zone_16`, `Zone_CRIT`, `Zone_GAS` to hex.

### Camera lock

`camera_transforms.json` stores each camera's world matrix at render time. The render script compares
them before and after rendering: no camera moved.
